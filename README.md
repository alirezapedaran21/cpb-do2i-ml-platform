# CPB DO₂i ML Platform

A reproducible, production-style machine learning project for forecasting the oxygen delivery index (DO₂i) during cardiopulmonary bypass (CPB).

> **Research prototype only.** This repository is for engineering demonstration and research. It is not a medical device, is not clinically validated, and must not be used to guide patient care or perfusionist settings.

## Project objective

Given information available at time *t* during CPB, forecast DO₂i at +5 and +10 minutes. The project will compare simple and ML baselines with a GRU model, then package the selected model as a tested inference service.

The exact target construction, feature availability timestamps, case-level data split, and metrics must be documented before model results are treated as final.

## Engineering goals

- Reproducible data preparation, training, and evaluation.
- Case-level train/validation/test separation to prevent patient/case leakage.
- Explicit feature and target definitions, including measurement freshness.
- Experiment tracking and model lineage with MLflow.
- Data and artifact versioning with DVC where permitted by the source-data terms.
- Tested inference using ONNX Runtime and a FastAPI service.
- Containerized execution, CI checks, and operational monitoring.

## Planned architecture

1. Data ingestion and validation
2. Time alignment and feature engineering
3. Case-level splitting and baseline evaluation
4. GRU training and model selection
5. ONNX export and parity testing
6. FastAPI inference service
7. Docker packaging and CI
8. Monitoring, model card, and reproducibility report

## Quick start (Windows PowerShell)

Install `uv`, then from the repository root run:

```powershell
uv lock
uv sync --all-groups
uv run pytest
uv run ruff check .
```

The lockfile generated by `uv lock` should be committed. Use `uv sync --locked --all-groups` on a clean machine or in CI to reproduce the resolved environment.

## Data access and governance

Raw data are intentionally not included in this repository. Follow the source dataset's terms, document the dataset version and access date, and do not publish patient-level records or derived files that could expose sensitive information.

If using VitalDB, review its current data-use agreement and license before redistribution or any commercial use. The published dataset terms identify CC BY-NC-SA 4.0; attribution, non-commercial use, and share-alike obligations therefore need to be respected. See <https://vitaldb.net/dataset/>.

## Reproducibility contract

A result is considered reproducible only when the repository records:

- code commit and dependency lockfile;
- dataset source/version and a checksum or DVC pointer (where allowed);
- split manifest at the case level;
- configuration and random seeds;
- preprocessing and feature definitions;
- model checkpoint and/or ONNX artifact identifier;
- evaluation script and metrics.

## Current status

This repository is a starter scaffold. Existing model code and checkpoints have not yet been audited or migrated. Do not treat historical metrics as final until the evaluation pipeline has been reproduced from the documented data and split.
